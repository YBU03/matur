# Additional, SO outlet dan pengeluaran POS — 28 Oktober 2026

Disetujui pemilik setelah overview. Tidak mengaktifkan/mematikan switch alur shift, tidak menghapus data pelatihan, dan tidak mengubah mesin transaksi/offline.

- Gudang → Additional & Varian: memakai master varian yang sudah ada. Per menu, grup Gula untuk Normal/Less/No Sugar (satu pilihan per grup), Extra untuk beberapa tambahan. Harga rupiah nol atau lebih; kosong dinormalisasi menjadi nol. Harga menu + tambahan memakai perhitungan POS asli. Katalog offline tetap snapshot lama sampai online.
- Karyawan/POS → Stok Outlet → Hitung stok / SO Outlet: input kemasan + sisa, impor/template Excel, pencarian, konfirmasi dan riwayat rinci (sistem/fisik/selisih, waktu, petugas). Pegawai hanya outlet penugasannya; nilai keuangan tetap di admin. Baris kosong tidak mengubah stok. Server mengecek snapshot jumlah stok, mengunci baris, menolak stale/duplikat/negatif/tanggal mendatang, dan menyimpan request ID agar retry tidak menggandakan mutasi.
- Nilai snapshot SO parsial mencakup seluruh stok bahan aktif outlet, bukan hanya bahan yang diisi. Harga nilai persediaan mengikuti aturan yang sudah ada (harga Gudang, fallback beli, dibagi konversi). Laporan terbit/penutupan Finance tetap prioritas. Data SO lama tidak dihitung ulang otomatis.
- POS → Kas & Pengeluaran: sumber laci menempel pada satu kas tim terbuka terbaru (dikunci saat simpan), sumber pusat tidak mengurangi laci. Request ID mencegah pengulangan insert. Marketing berupa uang dan produk endorse adalah pencatatan terpisah; produk memakai RPC/resep/mutasi lama. Kesalahan jaringan ditampilkan tanpa mengosongkan form. Edit/hapus tetap melalui RLS, batas 2 hari dan larangan mengubah kas final.
- Pemeriksaan membuktikan peran tablet sudah dipetakan ke kasir/barista di database; tidak ada pelonggaran helper izin global. RPC baru berupa public SECURITY INVOKER menuju schema privat tersendiri dengan guard pengguna aktif/outlet. Tidak memberi USAGE schema matur_internal.
- Opname Gudang terpisah `/gudang/opname`: draft, finalisasi snapshot, dan laporan Gudang tetap menggunakan jalur sebelumnya. Finance melihat, Gudang/Pusat/Owner mengelola. Menu Opname Outlet ditambahkan ke Gudang/Pusat yang belum memilikinya.

Verifikasi: pengujian PostgreSQL lokal (PGlite) untuk SO parsial/retry/stale/izin/validasi dan pengeluaran laci/pusat/closed; fixture `supabase/tests/pos_so_pengeluaran.sql` menggunakan akun outlet, barista dan Gudang terisolasi lalu ROLLBACK. Fixture Gudang lama juga dijalankan kembali. TypeScript, lint, seluruh unit test dan build wajib lulus sebelum deploy.
