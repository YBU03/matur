# SO harian dan cadangan hitungan

Laporan Kominot: server terakhir menyimpan SO 10 November. Log 15 November 12:28 dan 12:36 WIB menolak `simpan_opname_terukur` karena stok berubah selama menghitung. Form juga mensyaratkan review, sehingga tombol simpan terlihat redup meskipun semua bahan terisi.

## Hasil perubahan

- Tombol Periksa & simpan SO membuka rincian selisih, lalu Konfirmasi & simpan SO. Error juga tampil dekat tombol, dengan nomor bukti hanya ketika server memberikan ID opname.
- Konflik stok mengambil stok terkini dengan RLS, menandai hanya bahan berubah dan meminta hitung fisik ulang/konfirmasi per bahan. Mengganti pembanding tidak dilakukan diam-diam. RPC resmi tetap memeriksa snapshot dalam transaksi; penjualan yang terjadi lagi dapat menimbulkan konflik baru yang harus diperiksa.
- Isian dan snapshot dibekukan saat percobaan simpan. Bila jawaban terputus, request ID dan payload disimpan utuh. Cek / kirim ulang menggunakan payload sama, termasuk sesudah reload, sehingga commit yang sudah berhasil tidak digandakan. Kunci sementara hanya form SO, bukan POS/penutupan kas.
- Draft lokal versi 2 dipisahkan per pengguna/outlet/kas dan memiliki ID serta tanggal masing-masing. Draft lama disalin tanpa menghapus kunci asli. Dropdown menyediakan arsip, tombol hitungan baru dan unduh cadangan JSON. Perangkat tanpa ruang/izin penyimpanan menampilkan peringatan, bukan klaim tersimpan.
- Draft dicadangkan ke `draft_opname_outlet` melalui RPC SECURITY INVOKER dan RLS milik pengguna + izin outlet. Tidak ada trigger stok pada tabel draft. Versi lebih lama tidak dapat menimpa versi baru atau tanda final; perangkat berbeda dapat memiliki draft ID berbeda. Cadangan otomatis bersifat best-effort dengan status jelas, bukan antrean finalisasi stok otomatis.
- Arsip final terkunci untuk baca, dan nomor bukti merujuk opname resmi. Draft lebih lama dari kemarin hanya arsip; hitungan baru harus dilakukan. Tanggal kemarin tetap dapat dipakai saat tutup shift melewati tengah malam, dengan konfirmasi bahwa hitungan baru dilakukan. Tidak merekonstruksi atau menerapkan hitungan hilang 11–15 November ke stok hari ini.
- Pergantian kas memuat ulang komponen sesuai scope agar draft antarshift tidak tercampur. Penutupan kas tetap opsional terhadap SO, mengikuti pengaturan yang sudah ada.

## Verifikasi

- PGlite: draft antarhari/scope, versi respons terlambat, arsip final, penolakan lintas pengguna/outlet/anon; tes SO lama tetap melindungi stale stock, retry dan valuasi.
- Browser komponen asli dengan server uji terisolasi: isi 7 dan 0, konflik kopi 10→8, konfirmasi hitung ulang hanya kopi, respons terputus setelah commit, reload, retry menghasilkan satu SO dengan fisik tetap 7 dan 0. Arsip final dapat dibaca. Mock/halaman sementara dihapus sebelum build.
- Database produksi: cadangan draft diuji sebagai akun tablet Kominot dalam transaksi rollback. Jalur SO resmi juga diuji dengan 32 bahan dan retry satu bukti dalam transaksi rollback; tidak meninggalkan data SO uji atau mengubah stok operasional.

Pemeriksaan akhir: 515 tes pada 89 berkas lulus; enam tes draft/SQL diulang setelah nama migrasi diselaraskan dan lulus. TypeScript dan ESLint berkas perubahan lulus. Build produksi lokal lulus; pengecekan advisor tidak menambah temuan pada tabel/RPC draft. Migrasi 20261116023852 diterapkan; tabel baru tetap RLS aktif, anon tidak bisa baca/menulis, dan tidak ada data uji yang tersimpan. Event online mencoba kembali cadangan draft saja, bukan menerapkan stok otomatis.
